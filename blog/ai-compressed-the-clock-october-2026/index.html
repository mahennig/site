October 2026: AI didn’t change the attacks. It changed the clock.

27 Nov 2026 5 min read

October 2026 shipped a lot of vulnerabilities, and as usual most came with a name and half of them with a logo. Several involved AI. I read the primary sources instead of the headlines. My take: the techniques were mostly old. What changed is the time you get to react.

AI found the bugs. Humans still ran the process.

On 21 October, PHP shipped patches for CVE-2026-109618 and CVE-2026-109619. Wiz Research calls the pair PHP2Shell. These are memory-safety bugs in the engine itself, so every application on top inherits them. Wiz says nearly every PHP version back to 5.4 is affected.

The timeline matters more than the name. Wiz found the first bug on 19 August using its own tooling plus frontier models. Unauthenticated code execution worked against Drupal the next day and WordPress the day after. The report went to the PHP team on 24 August, and patches landed two months later. This was not “AI hacked PHP”: The New Stack reports that Calif found one bug with an OpenAI model, Wiz found both independently, and the maintainers led the fixes. Wiz also says one researcher did in a week what once took a strong team months. That is a vendor estimate without published metrics, so I read it as a signal, not a measurement.

The runtimes you forgot you ship

Node.js. The same Wednesday, which made Patch Tuesday look relaxed, Node released fixes for ten vulnerabilities across 22.x, 24.x and 26.x. The headline is CVE-2026-111497, an out-of-bounds write in the bundled Brotli decoder. It is reachable through node:zlib and through fetch() whenever a response arrives Brotli-compressed. The Hacker News notes that there is no workaround, Node 20 and older get nothing, and the fix had sat in Brotli’s source since February before it shipped as a security release. Eight months in the upstream source is not a secret. It is just unshipped. On 22 October nobody reported exploitation, and the public proof of concept only reached code execution on a deliberately weakened build. Five days later CISA listed it as exploited.

nginx. Two rounds. On 14 October F5 issued an out-of-band notice. According to the Singapore CSA advisory, three of the flaws are memory-corruption bugs rated 9.2 under CVSS 4.0. Read the fine print: they need specific configuration (alias with rewrite, async I/O with SSI, unnamed regex captures in map), and code execution is possible only if ASLR is disabled or bypassed. This is the kind of CVE where nginx -T tells you more than the score does.

The sequel arrived on 18 November: two HTTP/2 flaws, CVE-2026-123633 and CVE-2026-123007, both 9.2. Wiz reported the first on 21 October, found both with its own agent harness, and used frontier models to validate impact. Anything with HTTP/2 enabled up to 1.31.8 is affected. The fixes are 1.30.7 and 1.31.9, and http2 off; is the stop-gap. This one is not an October story, but it started in October.

Java4Shell. Log4Shell started a naming trend, and five years later naming is the one thing in this industry with full adoption. CVE-2026-114938 is also a November story: Oracle shipped the fix on 17 November, and CISA issued an alert the same day. It is a heap out-of-bounds write in HotSpot’s x86-64 Base64 intrinsic and only bites on CPUs with AVX-512 VBMI. But it belongs here, because of what Calif’s write-up shows. Someone hit the crash in June. A fix was proposed in September and closed unmerged. On 24 October a Calif researcher pointed OpenAI’s Codex at Netty and the JVM, and the agent found the bug in about an hour. Calif puts the first working exploit at two more hours and the token cost under $200. Those numbers are their own. They demonstrated pre-auth RCE against Jenkins, Keycloak, Jira, Confluence, Artifactory and PingFederate. The workaround is -XX:-UseBASE64Intrinsics. Qualys notes that October’s builds are still vulnerable.

The poisoned AI library was a very old failure

Also on 21 October, a malicious litellm 1.107.0 appeared on PyPI. The wheels were live from 11:39 to 13:23 UTC, the Docker tags until 14:20 UTC, and it stole cloud and AI credentials. The project’s post-mortem contains no AI magic. An administrative key was committed to a public repository in May and nobody followed through on revoking the administrative key. In October the attacker used it to pull a GitHub owner token out of an internal agent platform. That token was unscoped and could override branch protection. A two-person release gate had been relaxed that week, so stolen tokens satisfied both approvals. Defense in depth, as practiced: every layer was there, and every layer was open.

Agents that keep going

Amazon published findings last week about a campaign from 8 to 10 September. According to the AWS Security Blog, an operator gave the open-source agent framework Cairn a list of IP addresses and the goal “obtain shell access”. The agents found and exploited a path traversal flaw in a medical imaging application, 11 minutes from mapping the API to arbitrary file writes. Against a Redis target they burned 16 hours and 148 actions without success. The agents were not geniuses. They were tireless.

Microsoft’s 2026 Digital Defense Report points the same way. Per GCN’s summary, exploitation of public-facing applications rose from 15% to 24% of investigated intrusions, and the median time from discovery to weaponization is well under 24 hours. Microsoft also says complex intrusions still retain meaningful human direction. I find that balance credible.

What I would change on Monday

This is my opinion, not a finding from any of these reports.

  • Measure patch time in hours for anything internet-facing. A monthly cycle assumes attackers need weeks.
  • Inventory what you bundle, not only what you install. Node carries its own Brotli. The JVM carries its own intrinsics. Your scanner probably reads package.json.
  • Know which configuration makes a CVE reachable. Half of the nginx list needs a directive you may not use. The other half needs HTTP/2, which you do.
  • Make every credential short-lived and narrowly scoped. Blast radius is an architecture decision.
  • Treat release pipelines as production. Two-person approval means two independent identities. A rule that can be relaxed in a week is not a control.
  • Retire end-of-life runtimes. Node 20 gets no Brotli fix. “We’ll migrate next quarter” is not a mitigation.
  • Automate the response, not only the alert. If an attacker needs eleven minutes, a ticket queue is too slow.

None of this is new. That is the point. AI did not invent a weakness in October. It shortened the time between a weakness existing and someone using it. The boring fundamentals now have a deadline, and the deadline does not read your change calendar.
