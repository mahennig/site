October 2026: AI didn’t change the attacks. It changed the clock.

27 Nov 2026 7 min read

October 2026 was loud. AI models helped find critical bugs in PHP. A poisoned release of an AI library stole credentials for a couple of hours. Autonomous agents went after targets with almost no human steering. It is tempting to call all of this a new era.

I read the primary sources instead of the headlines. My take: the techniques were mostly old. What changed is the time you have to react.

AI found the bugs. Humans still ran the process.

On 21 October, PHP shipped patches for two critical flaws, tracked as CVE-2026-109618 and CVE-2026-109619. Wiz Research calls the pair PHP2Shell. The bugs sit in the PHP engine itself, so every application on top inherits them. Wiz says nearly every PHP version back to 5.4 is affected.

The timeline is the interesting part. Wiz found the first bug on 19 August using its own tooling plus frontier models. Unauthenticated code execution worked against Drupal the next day and against WordPress the day after. The report to the PHP team went out on 24 August. Patches landed two months later, after a coordinated disclosure with PHP, OpenAI and others.

Two cautions. First, this was not “AI hacked PHP.” The New Stack reports that Calif found one bug with an OpenAI model, Wiz found both independently, and the PHP maintainers led the fixes. Humans directed the work. Second, Wiz says one researcher did in a week what would once have taken a strong team months. That is a vendor estimate without published metrics. I take it as a signal, not a measurement.

The poisoned AI library was a very old failure

On the same day, a malicious litellm 1.107.0 appeared on PyPI. The compromised wheels were live from 11:39 to 13:23 UTC, and the Docker tags stayed bad until 14:20 UTC. It stole cloud and AI credentials.

The project’s own post-mortem is worth reading in full. No AI magic is involved. An administrative key had been committed to a public repository in May. It was never revoked. In the project’s words, nobody followed through on revoking the administrative key. In October the attacker used it to pull a GitHub owner token out of an internal agent platform. That token was unscoped and could override branch protection. A two-person release gate had been relaxed earlier that week, so stolen tokens could satisfy both approvals.

Count the failures: a leaked key, a token with too much power stored in a place that did not need it, CI secrets reachable by modifiable workflows, a weakened approval rule. I would find every one of these in a classic architecture review.

Agents that keep going

Amazon published findings last week about a campaign from 8 to 10 September. According to the AWS Security Blog, an operator gave an open-source agent framework called Cairn a list of IP addresses and a goal: get shell access. The agents then found and exploited a path traversal flaw in a medical imaging application. Eleven minutes passed between mapping the API and writing arbitrary files on the server.

The same report shows the other side. Against a Redis target, the agents spent about 16 hours and 148 actions without success. Against a university server they tried more than 30,000 credential combinations. Nothing worked. The agents were not geniuses. They were tireless.

Microsoft’s 2026 Digital Defense Report, published on 1 October, points the same way. According to GCN’s summary, exploitation of public-facing applications rose from 15% to 24% of the intrusions Microsoft investigated. The median time from discovery to weaponization is now well under 24 hours. Microsoft also says complex intrusions still retain meaningful human direction. I find that balance credible.

What I would change on Monday

This is my opinion, not a finding from any of these reports.

  • Measure patch time in hours for anything internet-facing. A monthly patch cycle assumes attackers need weeks. They do not.
  • Make every credential short-lived and narrowly scoped. The LiteLLM chain worked because one token could do almost everything. Blast radius is an architecture decision.
  • Treat release pipelines as production. Two-person approval means two independent identities. If a rule can be relaxed in a week, it is not a control.
  • Assume your AI tooling holds secrets. Agent platforms, gateways and proxies collect keys by design. Inventory them like databases.
  • Automate the response, not only the alert. If an attacker needs eleven minutes, a ticket queue is too slow.

None of this is new. That is the point. AI did not invent a weakness in October. It shortened the time between a weakness existing and someone using it. The boring fundamentals now have a deadline.
